# Solar Active Region Detection Pipeline — Aditya-L1 SUIT Imagery

A pipeline to detect, segment, and validate solar active regions from Level-1 imagery captured by the **SUIT** (Solar Ultraviolet Imaging Telescope) instrument aboard **Aditya-L1**, India's first dedicated solar observatory. Built as part of the **India Space Academy (ISA) Summer Training Program 2026** in heliophysics.

## Overview

Active regions are the sunspot-associated zones on the Sun where flares and coronal mass ejections (CMEs) originate. This project builds an end-to-end pipeline that:
- Preprocesses raw SUIT NB03 imagery (flat-field correction, normalization, disk masking)
- Detects active regions using two independent segmentation methods (Otsu thresholding, K-means clustering)
- Validates detections against NOAA's official active region catalog via the Heliophysics Event Knowledgebase (HEK)
- Tracks a detected region's evolution over multiple days and evaluates detection sensitivity across threshold values

One detected region, **AR14436**, produced an M5.7-class flare and a CME (~650 km/s) the day after detection — an independent confirmation that the pipeline correctly identified a pre-eruptive active region.

## Data Access

Raw FITS files are **not included in this repository** due to file size and ISRO data distribution policy. To reproduce this pipeline:

1. Download the following file(s) from ISRO's [PRADAN portal](https://pradan.issdc.gov.in/al1/):
   - `SUT_T26_0649_002132_Lev1.0_2026-05-09T07.09.21.400_08B2NB03.fits` (09 May 2026, 07:09:21 UTC, NB03 filter — 279.6 nm)
   - For Part2A (temporal evolution): equivalent NB03 files for 07–12 May 2026, ~07:09:21 AM each day
2. Place downloaded files in `Data/Raw/`
3. Run `Part1/Part1.ipynb` first — it generates `arr_2d_masked.npy` and `off_disk_removed.npy` in `Data/Processed/`, which are required inputs for `Part2C.ipynb` and `Part3.ipynb`

## Execution Order

Notebooks have dependencies and should be run in this order:
1. **`Notebooks/Part1.ipynb`** — must run first (generates processed arrays used downstream)
2. **`Notebooks/Part2A.ipynb`** — independent, requires its own set of daily FITS files
3. **`Notebooks/Part2C.ipynb`** — requires `arr_2d_masked.npy` from Part 1
4. **`Notebooks/Part3.ipynb`** — requires `arr_2d_masked.npy` from Part 1

## Methods Summary

| Part | Method | Result |
|------|--------|--------|
| 1 | Otsu thresholding (global) | 61 blobs, 7 unique NOAA ARs matched |
| 2A | Temporal tracking (AR14436 area, 6 days) | Evolution profile of a single AR |
| 2C | K-means (k=3) vs. Otsu | K-means: 159 blobs (min_area=100), 5 unique NOAA ARs |
| 3 | Otsu threshold sensitivity (0.40–0.65) | Detection count vs. threshold curve |

## Key Dependencies

- `sunpy` (map handling, Fido/HEK queries, coordinate transforms)
- `astropy` (units, coordinates)
- `scikit-image` (thresholding, labeling, region properties)
- `numpy`, `matplotlib`

## Known Limitations

- Global Otsu thresholding fragments single active regions into multiple blobs (61 blobs → only 7 unique ARs)
- File paths in notebooks use Windows-style separators; adjust for macOS/Linux
- Single-image analysis (Parts 1, 2C, 3) does not capture temporal evolution — see Part 2A for the time-series approach
- A fixed area cutoff for artifact removal (used in Part 1) does not generalize across threshold values — Part 3 addresses this with an adaptive 99th-percentile cutoff
